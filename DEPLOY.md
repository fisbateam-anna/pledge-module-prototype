# Постоянная публикация прототипа

## Факт

- Прототип статический: `index.html`, `src/app.js`, `src/data.js`, `src/styles.css`.
- Backend, база данных, Node.js и сборка не требуются.
- Старая ссылка `*.lhr.life` была временным туннелем и не может считаться постоянной.

## Готовая публичная ссылка после деплоя

После публикации папки `Новый_прототип` на статическом хостинге рабочий адрес должен быть:

```text
https://<домен-хостинга>/Залоговый_модуль/#/app/tasks
```

Также будет работать корневой вариант:

```text
https://<домен-хостинга>/#/app/tasks
```

## Рекомендуемый вариант: GitHub Pages

1. Создать новый GitHub-репозиторий, например `pledge-module-prototype`.
2. Загрузить в него содержимое папки `Новый_прототип`.
3. В настройках репозитория открыть `Settings -> Pages`.
4. Включить публикацию из ветки `main`, папка `/root`.
5. Использовать ссылку:

```text
https://<github-user>.github.io/pledge-module-prototype/Залоговый_модуль/#/app/tasks
```

## Альтернативы

- Netlify: загрузить папку `Новый_прототип` как статический сайт, build command не нужен, publish directory `.`.
- Vercel: импортировать папку как статический проект, framework preset `Other`, build command не нужен.
- Cloudflare Pages: создать Pages project, загрузить папку как static assets, build command не нужен.

## Что нельзя использовать как постоянную ссылку

- `localhost`
- `127.0.0.1`
- случайные `*.lhr.life`
- случайные `*.trycloudflare.com`

Это временные адреса для локальной демонстрации, они перестают работать при остановке туннеля или изменении сессии.
